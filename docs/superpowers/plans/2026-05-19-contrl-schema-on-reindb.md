# Contrl Schema on Reindb Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move contrl's 5 mirror-sync tables off its standalone Supabase project and onto the shared reindb project, under a new `contrl` schema.

**Architecture:** Per-app migrations under `contrl/supabase/migrations/`. Local SQLite preserved through cutover; `sync_state.last_pushed_at` is NULL'd to force a full re-push to the new project. One-line `db: { schema: 'contrl' }` addition to the Supabase client makes every existing `supabase.from(...)` call resolve under `contrl.*`.

**Tech Stack:** React Native + Expo, `@supabase/supabase-js`, Supabase CLI, Supabase Postgres (reindb).

**Testing approach:** This project has no test infrastructure (no Jest, no test deps). Verification is integration-style — query reindb dashboard, inspect local SQLite via `adb run-as`, observe push behavior in Metro logs. Each task ends with a concrete verification step.

**Spec:** [`docs/superpowers/specs/2026-05-19-contrl-schema-on-reindb-design.md`](../specs/2026-05-19-contrl-schema-on-reindb-design.md)

## Prerequisites (before Task 1)

Three values you'll need:

1. **reindb's project URL** (e.g., `https://xxxxxxxxx.supabase.co`). From the reindb dashboard → Settings → API → "Project URL", OR from `~/Public/buffr/.env` line `EXPO_PUBLIC_SUPABASE_URL=...`.
2. **reindb's anon public key**. Same dashboard page → "anon public key", OR from `~/Public/buffr/.env` line `EXPO_PUBLIC_SUPABASE_ANON_KEY=...`. Format starts with `sb_publishable_` or is a long JWT-shaped string.
3. **reindb's project ref** (the 20-character ID from the URL — e.g., for `https://xxxxxxxxx.supabase.co` the ref is `xxxxxxxxx`). Or run `supabase projects list` while logged in.

The Supabase CLI must be available. Check with `supabase --version`. If missing: `brew install supabase/tap/supabase` (macOS Homebrew).

- [ ] **Step 2: Write `0001_contrl_schema.sql` with this exact content**

```sql
-- Contrl mirror-sync schema on reindb.
-- Hosts contrl alongside buffr under separate schemas in one Supabase project.
-- See docs/superpowers/specs/2026-05-19-contrl-schema-on-reindb-design.md
--
-- AFTER APPLYING THIS MIGRATION, two out-of-band steps are required:
--   1. Supabase dashboard for reindb → Settings → API → "Exposed schemas"
--      → add `contrl` to the list (next to `public`, `buffr`).
--   2. Update contrl/.env and contrl/src/services/sync/client.ts per
--      the cutover plan.

BEGIN;

CREATE SCHEMA IF NOT EXISTS contrl;

GRANT USAGE ON SCHEMA contrl TO anon, authenticated, service_role;

-- Default privileges for any FUTURE tables created inside `contrl`.
ALTER DEFAULT PRIVILEGES IN SCHEMA contrl
  GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO anon, authenticated, service_role;

CREATE TABLE IF NOT EXISTS contrl.user_profile (
  user_id      uuid PRIMARY KEY,
  push_level   int NOT NULL,
  pull_level   int NOT NULL,
  squat_level  int NOT NULL,
  created_at   timestamptz,
  updated_at   timestamptz NOT NULL
);

CREATE TABLE IF NOT EXISTS contrl.exercises (
  user_id       uuid NOT NULL,
  id            text NOT NULL,
  name          text NOT NULL,
  category      text NOT NULL,
  level         int  NOT NULL,
  target_sets   int  NOT NULL,
  target_reps   int  NOT NULL,
  sort_order    int  NOT NULL DEFAULT 0,
  tempo         text,
  notes         text,
  updated_at    timestamptz NOT NULL,
  PRIMARY KEY (user_id, id)
);

CREATE TABLE IF NOT EXISTS contrl.sessions (
  user_id         uuid NOT NULL,
  id              text NOT NULL,
  date            timestamptz NOT NULL,
  level           int  NOT NULL,
  category        text NOT NULL,
  exercises_json  jsonb NOT NULL,
  notes           text,
  passed          boolean,
  updated_at      timestamptz NOT NULL,
  PRIMARY KEY (user_id, id)
);

CREATE TABLE IF NOT EXISTS contrl.gate_progress (
  user_id            uuid NOT NULL,
  id                 text NOT NULL,
  level              int  NOT NULL,
  category           text NOT NULL,
  status             text NOT NULL,
  consecutive_passes int  NOT NULL DEFAULT 0,
  last_session_date  timestamptz,
  updated_at         timestamptz NOT NULL,
  PRIMARY KEY (user_id, id)
);

CREATE TABLE IF NOT EXISTS contrl.week_progress (
  user_id     uuid NOT NULL,
  week_start  date NOT NULL,
  push_done   boolean NOT NULL DEFAULT false,
  pull_done   boolean NOT NULL DEFAULT false,
  squat_done  boolean NOT NULL DEFAULT false,
  updated_at  timestamptz NOT NULL,
  PRIMARY KEY (user_id, week_start)
);

-- RLS deliberately not enabled. Phase A model: single hardcoded USER_ID,
-- anon-key access only. Adding RLS is a future migration.

COMMIT;
```

## Task 9: Reset the push watermark to force a full re-push

**Files:** none in repo — modifies the SQLite file inside the app's sandbox on the phone.

The previous `last_pushed_at` value reflects pushes to the OLD project. Without resetting it, `pushChanges()` would filter all rows out (`updated_at <= since`) and the new project would stay empty.

- [ ] **Step 1: Confirm the phone is connected**

```bash
adb devices
```

Expected: a single device listed with state `device`. If empty, plug in / unlock the phone.

- [ ] **Step 2: Ensure the app is not running**

```bash
adb shell am force-stop com.rein.contrl
```

This prevents concurrent writes to the SQLite file while we modify it.

- [ ] **Step 3: Pull the database to a local temp**

```bash
adb exec-out run-as com.rein.contrl cat files/SQLite/contrl.db > /tmp/contrl-reset.db
ls -la /tmp/contrl-reset.db
```

Expected: a file of non-trivial size (tens of KB or more).

- [ ] **Step 4: NULL out `last_pushed_at`**

```bash
sqlite3 /tmp/contrl-reset.db "UPDATE sync_state SET last_pushed_at = NULL WHERE id = 'default'"
sqlite3 /tmp/contrl-reset.db "SELECT * FROM sync_state WHERE id = 'default'"
```

Expected last command output: `default||<last_pulled_at value>` — `last_pushed_at` column is empty, `last_pulled_at` keeps its value (we don't want to force a pull).

- [ ] **Step 5: Push the modified db back to the phone**

```bash
adb push /tmp/contrl-reset.db /sdcard/Download/contrl-reset.db
adb shell "cat /sdcard/Download/contrl-reset.db | run-as com.rein.contrl tee files/SQLite/contrl.db > /dev/null"
adb shell rm /sdcard/Download/contrl-reset.db
rm /tmp/contrl-reset.db
```

- [ ] **Step 6: Confirm the in-place watermark is NULL**

```bash
adb exec-out run-as com.rein.contrl sh -c 'cat files/SQLite/contrl.db' \
  | sqlite3 - "SELECT last_pushed_at FROM sync_state WHERE id = 'default'" 2>/dev/null
```

If that command shape doesn't work, fall back to the round-trip:

```bash
adb exec-out run-as com.rein.contrl cat files/SQLite/contrl.db > /tmp/contrl-check.db
sqlite3 /tmp/contrl-check.db "SELECT last_pushed_at FROM sync_state WHERE id = 'default'"
rm /tmp/contrl-check.db
```

Expected: a blank line (NULL has no value to print).
